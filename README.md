# WING SOUND ACADEMY

个人音乐学院数字教务平台。React + TypeScript + Vite，Local-first，无需账户与后端。

## 本地启动

推荐 Node.js 22.10+，已在 Windows / Node.js 22.10 上验证。

```bash
npm install
npm run dev
```

打开 **http://127.0.0.1:5173/**。端口固定，若已占用则明确退出，避免切换端口后看不到原浏览器记录。请始终使用同一浏览器及这个地址。`localhost`、`127.0.0.1`、不同端口和正式域名的存储相互独立。

```bash
npm test          # 日期边界、数据校验、音频备份恢复
npm run build    # TypeScript 检查与生产构建
npm run preview  # 生产包预览：http://127.0.0.1:4173/
```

预览地址与开发地址不同，记录不会自动互通，可通过完整备份迁移。不要直接双击 dist/index.html。

## 已实现

- 总览：学院品牌、当前教学周、下次课程、当前/首个项目、16周时间轴、近期课程节点与最近创作记录。
- 课表：16周全部真实课程、项目分组、作品讲评节点、W09弹性周；任意周次均可进入详情。
- 周次详情：教学目标、任务、提交内容；自动保存笔记、参考资料与个人进度；手动状态管理；可编辑日期和课程配置。
- 项目：P00–P04创作任务书、研究问题、限制、研究主题与阶段里程碑；创作想法、修改日志、结题总结、作品档案及关联作品讲评；创作任务文字可直接修改。
- P04：独立的五阶段进度和 Final Presentation 展示。每个阶段可独立标记与撤销，项目总状态独立维护。
- 作品讲评：新建、编辑、删除、项目筛选、音频版本关联、创作者陈述、聆听反馈、优势、带音频时间位置的问题、修改方向和待解决问题。修改自动保存，无数字评分。
- 档案：音频版本、笔记、声音素材、参考音乐、结题总结；项目筛选、版本标记、最终成果标记、编辑与删除；本地音频和外部链接。
- 完整备份导出/导入：文字及本地音频共同打包为 JSON。导入前检查结构、日期、项目关联、版本关联及音频完整性；无效导入不覆盖现有记录。
- 响应式界面、键盘焦点、原生模态对话框、存储失败提示、损坏数据保护与原始记录恢复下载。

所有个人记录初始为空。日期只定位教学周和下次课程，**不会自动完成课程、项目或期末阶段**。课程在周日当天仍显示为下次课程，因为具体时段尚未确定。北京时间（Asia/Shanghai）用于日期计算。

## 可读性与旧数据兼容

正文16px，说明、状态、日期和导航至少14px，装饰性编号12px；主要按钮至少44px高。时间轴保留每周宽度，窄屏在模块内横向滚动，课表在手机上改为纵向排列。保留细线网格、黑白灰和电蓝视觉。

`labels.ts` 仅对已知旧枚举和完整默认文案做展示映射，不批量替换个人笔记或讲评原文。存储键、schemaVersion、记录ID、音频文件ID、版本关联和P04五阶段顺序均不变；旧JSON备份继续可导入。历史数据中的内部英文类型名保留，以兼容原有验证和备份。

## 日常使用与数据保存

1. 从首页「下次课程」进入周次详情，记录笔记并手动更新状态。
2. 在项目「创作过程」持续保存想法、修改依据与总结。
3. 在「作品版本与档案」添加音频或外部作品地址，然后在作品讲评中关联对应版本。
4. 从右上角「数据管理」定期导出完整备份。换设备或换部署域名时，先导出，再在新地址导入。

周次、项目和作品讲评的文字修改即时自动保存。新档案通过「保存档案」建立；已有档案的有效文字修改自动保存，替换音频附件需点击保存。课程配置表单需验证日期后确认保存。

文字存于 localStorage（键：`wing-sound-academy:v1`），本地音频存于 IndexedDB（数据库：`wing-sound-audio`）。它们仅存在当前浏览器和站点地址，**没有云端同步**。隐私窗口、浏览器清理与磁盘空间不足可能影响保存；出现保存错误时界面会提示导出当前数据。

完整备份包含音频原始字节，以 Base64 嵌入 JSON，体积约比原文件大三分之一。导入音频使用新文件ID，写入完成后才替换文字记录。外部链接只保存URL，无法保证远端资源永久有效，也不会复制远端音频文件。缺失本地附件时完整导出会报错，不会声称备份成功。

MP3 / WAV / OGG 等格式由浏览器原生播放器解码；FLAC / AIFF 等支持取决于浏览器。SoundCloud 等作品页面可通过链接打开，通常不能直接作为音频源播放。不提供波形编辑、转码或DAW功能。

大体积作品与大量音频的备份会占用内存，目前没有压缩ZIP、分块导入和云存储。请同时保留原始音频。删除档案会清除对应本地附件并取消作品讲评中的版本关联，作品讲评本身保留。

## 源码结构

```text
src/
  types.ts      学期、周次、项目、作品讲评、档案数据模型
  data.ts       完整真实课程与初始数据
  domain.ts     上海时区、学期定位、日期格式、链接检查
  labels.ts     音乐教学展示用语与旧枚举/默认文案兼容
  storage.ts    持久化仓库、数据校验、IndexedDB、完整备份
  App.tsx       应用状态、Hash路由、首页、目录与档案/作品讲评列表
  pages.tsx     课表、周次详情、项目详情与课程大纲
  editors.tsx   编辑器与数据管理对话框
  ui.tsx        统一视觉组件与音频播放器
  styles.css    全站网格、字体、响应式与交互样式
tests/          日期与备份完整性测试
```

课程和项目的配置均在 `data.ts`，首次使用时生成初始数据；之后以浏览器记录为准，修改源码初始数据不会覆盖已保存记录。日期与课程内容可在周次详情中编辑。正式教学日限定周日，并验证前后周次的日期顺序。

持久化逻辑集中在 `storage.ts`，UI使用统一 `AcademyData` 模型，便于以后将 repository 与音频适配器替换为 Supabase/Postgres + Object Storage。当前只管理一个16周学期，尚未实现多学期选择、账户登录与云同步。

字体优先使用 Google Fonts 的 DM Sans / IBM Plex Mono / Noto Sans SC，网络不可用时使用系统字体，不影响功能。图标来自 lucide-react。品牌标记及抽象信号图形由代码绘制。

## 部署

演示网站：[WING SOUND ACADEMY](https://yangzi831.github.io/wing-sound-academy/)。源码仓库：[yangzi831/wing-sound-academy](https://github.com/yangzi831/wing-sound-academy)。构建产物为静态 `dist/`，不含个人记录或音频。

**GitHub Pages**：`.github/workflows/deploy-pages.yml` 在推送到 `main` 后自动安装依赖、运行测试、构建并部署。仓库 Settings → Pages 的发布来源使用 GitHub Actions。Vite 使用相对资源路径，兼容项目子目录。正式站点可直接访问 `/#schedule`、`/#project/P04` 等 Hash 路由，无需启动本地服务。

**Netlify**：已提供 `netlify.toml`，构建命令 `npm run build`，发布目录 `dist`。

**Cloudflare Pages**：框架选 Vite，构建命令 `npm run build`，输出目录 `dist`；Node.js 推荐22。已提供 `public/_redirects`，Hash路由也可直接使用。

部署后仍采用浏览器本地存储；迁移数据必须先从旧地址导出、再导入新地址。云端托管静态网页不等于云端同步学习记录。
